Pedi uma IA para verificar se os dados estão corretos, ela me disse o seguinte:

1. A pegadinha do IS_qUnid (Ainda gravando valor)
No teste anterior, comentei sobre zerar o IS_qUnid quando o tipo de cálculo for 1 (Ad Valorem). Notei que ele continua salvando os valores de litragem (0,2690, 0,5380).

- O motivo do alerta: Se o layout do governo mantiver a validação estrita, o XML será rejeitado se a tag <qUnidIS> for informada junto com uma alíquota percentual.
- Ação no VB6: Force esse campo para 0 no banco quando IS_tipo_calculo = 1.

2. Arredondamento e Truncamento no IBS (Item 2 e Item 3)
O seu código de cálculo do IBS está truncando (jogando os centavos fora) em vez de arredondar. Isso vai dar rejeição na soma total da nota fiscal. Veja a matemática:
- No Item 2 (Base 2,50): * Parcela Estadual (vIBSUF): 2,50 X 0,12% = 0,003 
Seu sistema gravou 0,00. (Correto)
- Parcela Municipal (vIBSMun): 2,50 X 0,02% = 0,0005
Seu sistema gravou 0,00. (Correto)
-Total do IBS do Item (IBS_vIBS): O sistema gravou 0,00.
No Item 3 (Base 7,00) - Aqui está o erro crítico: * Parcela Estadual (vIBSUF): 7,00 X 0,12% =  0,0084 . O arredondamento correto de 0,0084 é 0,01. O seu sistema gravou 0,00 (truncou).
-Parcela Municipal (vIBSMun): 7,00 X 0,02% = 0,0014. O arredondamento correto é 0,00. 
O seu sistema gravou 0,01 (arredondou para cima incorretamente, deveria ser 0).
-Total do IBS do Item (IBS_vIBS): O sistema gravou 0,01, mas a soma interna foi de duas parcelas erradas.

3. A regra de soma do IBS (IBS_vIBS)
Por regra do layout, o campo IBS_vIBS deve ser a soma exata dos campos IBS_vIBSUF + IBS_vIBSMun.
-No Item 4: O sistema gravou IBS_vIBSUF = 0,01 e IBS_vIBSMun = 0,01. Porém, no campo IBS_vIBS (total), ele gravou 0,00. A soma de 0,01 + 0,01 tinha que dar 0,02. Se mandar o XML assim, o servidor da Receita rejeita na hora por erro de soma de totais.

* Como resolver isso definitivamente no código VB6:
Para matar esses problemas de centavos e somas, a sua rotina de cálculo do IBS antes do INSERT deve ser exatamente assim:

' --- CÁLCULO DO IBS NO ITEM ---
' 1. Calcula as parcelas usando Round para garantir o arredondamento de centavos
Var_IBS_vIBSUF  = Round(Var_IBS_vBC * (Var_IBS_UFpAliq / 100), 2)
Var_IBS_vIBSMun = Round(Var_IBS_vBC * (Var_IBS_MunpAliq / 100), 2)

' 2. Regra de Ouro: O total do item DEVE ser a soma das duas parcelas arredondadas
Var_IBS_vIBS = Var_IBS_vIBSUF + Var_IBS_vIBSMun

' --- AJUSTE DO IMPOSTO SELETIVO (EVITAR REJEIÇÃO) ---
If Var_IS_tipo_calculo = 1 Then
    Var_IS_qUnid = 0 ' Força zero se for Ad Valorem para não quebrar o XML
    Var_IS_vUnid = 0
End If

Fazendo o campo totalizar pela soma das parcelas arredondadas (Passo 2), a sua tabela fica matematicamente perfeita para passar em qualquer validador fiscal! O avanço de uma nota para a outra foi gigante, parabéns.
